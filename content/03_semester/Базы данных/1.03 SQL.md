#### Edgar Frank "Ted" Codd

1. Реляционная СУБД должна быть способна полностью управлять БД через ее реляционные возможности
2. Информационное правило - вся информация определяется строго как значения в таблицах, первичного ключа и имени столбца
3. Гарантированный доступ - любое значение должно быть гарантированно доступно для использования через комбинацию имени таблицы, значения
4. Поддержка пустых значений - с пустыми значениями работаем также, как и с заполненными (СУБД работает также, как и с заполненными, понимание дефекта)
5. Онлайновый реляционный каталог - описание БД и ее содержание должны быть представлены на логическом уровне как табицы, к которым можно применять запросы, используя язык БД
6. Исчерпывающий язык управления данными - *переписать*
7. Правило обновления представлений - все представления, теоритически обновляемые могут быть обновлены только через систему
8. Вставка, обновление и удаление - СУБД поддерживает вставку, обновление, удаление
9. Физическая независимость данных - программы логически не влияют на изменения физических методов доступа к данным и структур хранилищ данных
10. Логическая независимость данных - программы логически не влияют на структуру таблиц
11. Назависимость целостности - язык способен определять правило целостности, то есть нерушимость данных (использование доменнов)
12. Независимость распределения - результат всегда одинаков
13. Неподрывность - невзможность обойти праавила целостности, определенные через язык БД использованием ЯНУ.

## Предложения SQL

**DDL** :
- CREATE TABLE / INDEX / VIEW
- DROP TABLE / INDEX / VIEW
- TRUNCATE TABLE - очистка таблицы
- ALTER TABLE - изменение структуры

**DML** :
- INSERT - добавить
- DELETE - удалить записи
- UPDATE - обновить записи
- SELECT - выбрать

**Стандартые типы данных**:
- integer(size)
- int(size)
- smallint(size)
- tinyint(size)
- decimal(size, d)
- numeric(size, d)
- float
- char(size)
- varchar(size)
- date(yyyymmdd)

**Индекс** - для фильтрации и сортировки
