## Подзапросы (вложенный SELECT)

**Подзапрос** — запрос `SELECT`, расположенный внутри другого SQL-запроса. Результат подзапроса используется внешним запросом.

Общий вид:

```
SELECT column_name1
FROM table_name
WHERE column_name2 оператор_сравнения
    (SELECT column_name1
     FROM table_name
     WHERE условие);
```

Если подзапрос используется с обычным оператором сравнения (`=`, `>`, `<` и т. д.), он должен возвращать одно значение.

**Пример:**

```
SELECT SUM(Sales)
FROM Store_Information
WHERE Store_name IN
    (SELECT store_name
     FROM Geography
     WHERE region_name = 'West');
```

Запрос возвращает общую сумму продаж магазинов, расположенных в западном регионе (`West`).

Внутренний запрос выбирает названия магазинов из таблицы `Geography`, а внешний находит сумму их продаж в таблице `Store_Information`.

## EXISTS и NOT EXISTS

`EXISTS` и `NOT EXISTS` — операторы проверки существования записей в результате подзапроса.

- `EXISTS` — возвращает `TRUE`, если подзапрос содержит хотя бы одну строку.
    
- `NOT EXISTS` — возвращает `TRUE`, если подзапрос не содержит ни одной строки.
    

Общий вид:

```
SELECT столбцы
FROM таблица
WHERE EXISTS (подзапрос);
```

**Пример: товары, имеющиеся на складе**

```
SELECT Название
FROM Товар
WHERE EXISTS (
    SELECT КодТовара
    FROM Склад
    WHERE Товар.КодТовара = Склад.КодТовара
);
```

Подзапрос проверяет, существует ли на складе запись с кодом соответствующего товара.

**Пример: товары, отсутствующие на складе**

```
SELECT Название
FROM Товар
WHERE NOT EXISTS (
    SELECT КодТовара
    FROM Склад
    WHERE Товар.КодТовара = Склад.КодТовара
);
```

`EXISTS` и `NOT EXISTS` используются совместно с подзапросами. При проверке учитывается наличие строк, поэтому подзапрос может возвращать любое количество столбцов.

## Объединение запросов

Операторы объединения позволяют выполнять операции над результатами нескольких запросов `SELECT`.

Для объединяемых запросов количество столбцов и типы соответствующих столбцов должны быть совместимы.

### UNION

Объединяет результаты запросов и удаляет повторяющиеся строки.

```
SELECT Date
FROM Store_Information
UNION
SELECT Date
FROM Internet_Sales;
```

В результате получаем список дат из обеих таблиц без повторов.

### UNION ALL

Объединяет результаты запросов, сохраняя повторяющиеся строки.

```
SELECT Date
FROM Store_Information
UNION ALL
SELECT Date
FROM Internet_Sales;
```

В отличие от `UNION`, оператор `UNION ALL` не удаляет дубликаты.

### INTERSECT

Возвращает строки, присутствующие в результатах обоих запросов.

```
SELECT Date
FROM Store_Information
INTERSECT
SELECT Date
FROM Internet_Sales;
```

Результат содержит только общие даты двух таблиц.

### MINUS

Возвращает строки первого запроса, которых нет в результате второго запроса.

```
SELECT Date
FROM Store_Information
MINUS
SELECT Date
FROM Internet_Sales;
```

Результат содержит даты, присутствующие в `Store_Information`, но отсутствующие в `Internet_Sales`.

`MINUS` используется, например, в Oracle. В PostgreSQL аналогичная операция выполняется с помощью `EXCEPT`. Поддержка операторов зависит от СУБД.

## Соединение таблиц — JOIN

`JOIN` используется для объединения данных из нескольких таблиц на основании заданного условия.

Например, имеются таблицы `Employees` и `Orders`.

**Employees**

|Employee_ID|Name|
|---|---|
|01|Hansen, Ola|
|02|Svendson, Tove|
|03|Svendson, Stephen|
|04|Pettersen, Kari|

**Orders**

|Prod_ID|Product|Employee_ID|
|---|---|---|
|234|Printer|01|
|657|Table|03|
|865|Chair|03|

Поле `Employee_ID` связывает сотрудников с заказами.

### INNER JOIN

`INNER JOIN` возвращает только те строки, для которых найдено соответствие в обеих таблицах.

Общий вид:

```
SELECT столбцы
FROM первая_таблица
INNER JOIN вторая_таблица
    ON условие_соединения;
```

Пример:

```
SELECT Employees.Name, Orders.Product
FROM Employees
INNER JOIN Orders
    ON Employees.Employee_ID = Orders.Employee_ID;
```

Результат:

|Name|Product|
|---|---|
|Hansen, Ola|Printer|
|Svendson, Stephen|Table|
|Svendson, Stephen|Chair|

Сотрудники без заказов в результат не попадают.

### Условие отбора при JOIN

Чтобы определить, кто купил принтер, добавляем `WHERE`:

```
SELECT Employees.Name
FROM Employees
INNER JOIN Orders
    ON Employees.Employee_ID = Orders.Employee_ID
WHERE Orders.Product = 'Printer';
```

Результат — `Hansen, Ola`.

## GROUP BY — группировка

`GROUP BY` объединяет строки с одинаковыми значениями указанных столбцов в группы. Часто используется вместе с агрегатными функциями.

Общий вид:

```
SELECT столбец, агрегатная_функция(столбец)
FROM таблица
GROUP BY столбец;
```

Пример:

```
SELECT Company, SUM(Amount)
FROM Sales
GROUP BY Company;
```

Запрос группирует продажи по компаниям и вычисляет общую сумму продаж для каждой компании.

Без `GROUP BY` функция `SUM(Amount)` вычислила бы общую сумму по всем выбранным строкам, а не отдельно по каждой компании.

---
## HAVING — условие отбора групп

`HAVING` задаёт условие отбора уже сформированных групп.

Пример:

```
SELECT Company, SUM(Amount)
FROM Sales
GROUP BY Company
HAVING SUM(Amount) > 10000;
```

Запрос выводит только те компании, у которых общая сумма продаж превышает 10000.

**Разница между WHERE и HAVING:**

- `WHERE` отбирает отдельные строки до группировки.
    
- `HAVING` отбирает группы после группировки.

## SELECT INTO — создание таблицы из запроса

`SELECT INTO` позволяет создать новую таблицу на основе результата запроса и заполнить её выбранными данными.

Общий вид:

```
SELECT столбцы
INTO новая_таблица
FROM исходная_таблица
WHERE условие;
```

Пример: копирование всех столбцов и строк таблицы `Persons`:

```
SELECT *
INTO Persons_backup
FROM Persons;
```

Пример: создание резервной таблицы только с выбранными столбцами:

```
SELECT LastName, FirstName
INTO Persons_backup
FROM Persons;
```

Пример: копирование только записей, удовлетворяющих условию:

```
SELECT LastName, FirstName
INTO Persons_backup
FROM Persons
WHERE City = 'Sandnes';
```

Синтаксис `SELECT INTO` отличается в разных СУБД. Например, в PostgreSQL для создания таблицы по результату запроса обычно используется `CREATE TABLE ... AS SELECT ...`.

## Представления — CREATE VIEW

**Представление (VIEW)** — виртуальная таблица, основанная на результате SQL-запроса.

Представления позволяют сохранять запросы и обращаться к их результатам как к таблицам.

Общий вид:

```
CREATE VIEW view_name AS
SELECT столбцы
FROM table_name
WHERE условие;
```

Пример:

```
CREATE VIEW Current_Product_List AS
SELECT ProductID, ProductName
FROM Products
WHERE Discontinued = 0;
```

Представление `Current_Product_List` содержит идентификаторы и названия товаров, которые не сняты с продажи (если `0` обозначает отсутствие снятия с продажи).

Обращение к представлению:

```
SELECT *
FROM Current_Product_List;
```

Представление обычно хранит определение запроса, а не отдельную копию данных.

## DCL — Data Control Language

**DCL (Data Control Language)** — язык управления доступом к данным. Используется для предоставления, отзыва и запрета прав пользователей.

Основные команды:

- `GRANT` — предоставить права.
    
- `REVOKE` — отозвать ранее предоставленные права.
    
- `DENY` — явно запретить права в СУБД, поддерживающих эту команду, например Microsoft SQL Server.
    

### GRANT — предоставление прав

Общий вид:

```
GRANT привилегии
ON объект
TO пользователь;
```

Основные привилегии:

|Привилегия|Назначение|
|---|---|
|`SELECT`|Чтение данных|
|`INSERT`|Добавление записей|
|`UPDATE`|Изменение данных|
|`DELETE`|Удаление записей|
|`ALL PRIVILEGES`|Предоставление всех доступных привилегий в рамках команды и СУБД|
|`ALTER`|Изменение структуры таблицы|
|`INDEX`|Создание индексов|

Пример: предоставить пользователю `U1805` право читать таблицу `S`:

```
GRANT SELECT ON S TO U1805;
```

Предоставление нескольких прав:

```
GRANT SELECT, UPDATE
ON S
TO U1805;
```

Предоставление права чтения всем пользователям:

```
GRANT SELECT ON P TO PUBLIC;
```

`PUBLIC` обозначает всех пользователей в контексте прав доступа СУБД.

### REVOKE — отзыв прав

`REVOKE` отменяет ранее предоставленные привилегии.

Общий вид:

```
REVOKE привилегии
ON объект
FROM пользователь;
```

Пример:

```
REVOKE SELECT
ON S
FROM U1805;
```

После выполнения команды у пользователя отзывается предоставлённое этой привилегией право чтения таблицы `S`, если нет других оснований для доступа.

### DENY — явный запрет прав

`DENY` используется, например, в Microsoft SQL Server для явного запрета определённого действия.

Пример для SQL Server:

```
DENY SELECT
ON dbo.S
TO U1805;
```

Команда запрещает пользователю `U1805` выполнять `SELECT` над таблицей `dbo.S` с учётом правил разрешения конфликтов прав в SQL Server.

**Важно:** `DENY` не является универсальной командой стандартного SQL и поддерживается не всеми СУБД.

## Транзакции — COMMIT и ROLLBACK

**Транзакция** — последовательность операций с базой данных, которую рассматривают как единое целое.

Основные команды:

- `START TRANSACTION` — начало транзакции в поддерживающих эту форму СУБД.
    
- `COMMIT` — подтверждение изменений.
    
- `ROLLBACK` — отмена изменений текущей транзакции, которые ещё не были зафиксированы.
    

Пример:

```
START TRANSACTION;

UPDATE Accounts
SET Balance = Balance - 1000
WHERE Account_ID = 1;

UPDATE Accounts
SET Balance = Balance + 1000
WHERE Account_ID = 2;

COMMIT;
```

В примере 1000 денежных единиц переводятся с одного счёта на другой, после чего изменения фиксируются.

Если во время выполнения произошла ошибка и изменения ещё не зафиксированы, можно выполнить:

```
ROLLBACK;
```

Это отменит изменения текущей транзакции, которые подлежат откату.

### Блокировка таблиц

В некоторых СУБД используются команды:

- `LOCK TABLES` — блокировка таблиц.
    
- `UNLOCK TABLES` — снятие блокировок, установленных соответствующим механизмом.
    

Поддержка и синтаксис этих команд зависят от СУБД. В частности, приведённая в лекции форма характерна для MySQL.

## OUTER JOIN — внешнее соединение

**OUTER JOIN** — соединение таблиц, которое позволяет получить совпадающие записи и сохранить определённые записи без соответствий в другой таблице.

В отличие от `INNER JOIN`, внешнее соединение не исключает все строки, для которых не найдено соответствие: для отсутствующих данных со стороны другой таблицы возвращается `NULL`.

Существует три основных вида внешнего соединения.

### LEFT OUTER JOIN (LEFT JOIN)

Возвращает все строки из левой таблицы и соответствующие строки из правой таблицы. Если соответствия нет, столбцы правой таблицы содержат `NULL`.

Общий вид:

```
SELECT столбцы
FROM первая_таблица
LEFT JOIN вторая_таблица
    ON условие_соединения;
```

Пример:

```
SELECT Employees.Name, Orders.Product
FROM Employees
LEFT JOIN Orders
    ON Employees.Employee_ID = Orders.Employee_ID;
```

Результат:

|Name|Product|
|---|---|
|Hansen, Ola|Printer|
|Svendson, Tove|NULL|
|Svendson, Stephen|Table|
|Svendson, Stephen|Chair|
|Pettersen, Kari|NULL|

Все сотрудники присутствуют в результате, даже если у них нет заказов.

### RIGHT OUTER JOIN (RIGHT JOIN)

Возвращает все строки из правой таблицы и соответствующие строки из левой таблицы. Если соответствия нет, столбцы левой таблицы содержат `NULL`.

Общий вид:

```
SELECT столбцы
FROM первая_таблица
RIGHT JOIN вторая_таблица
    ON условие_соединения;
```

Пример:

```
SELECT Employees.Name, Orders.Product
FROM Employees
RIGHT JOIN Orders
    ON Employees.Employee_ID = Orders.Employee_ID;
```

В этом примере сохраняются все заказы, даже если для какого-либо заказа не найден соответствующий сотрудник. Если сотрудник найден, выводятся его имя и товар.

### FULL OUTER JOIN

Возвращает все строки обеих таблиц:

- строки, для которых найдено соответствие, объединяются;
    
- строки левой таблицы без соответствия сохраняются, а столбцы правой получают `NULL`;
    
- строки правой таблицы без соответствия тоже сохраняются, а столбцы левой получают `NULL`.
    

Общий вид:

```
SELECT столбцы
FROM первая_таблица
FULL OUTER JOIN вторая_таблица
    ON условие_соединения;
```

`FULL OUTER JOIN` поддерживается не всеми СУБД. Например, MySQL не поддерживает его напрямую.

### Сравнение видов JOIN

|Вид соединения|Что возвращает|
|---|---|
|`INNER JOIN`|Только совпадающие строки обеих таблиц|
|`LEFT JOIN`|Все строки левой таблицы и совпадения из правой|
|`RIGHT JOIN`|Все строки правой таблицы и совпадения из левой|
|`FULL OUTER JOIN`|Все строки обеих таблиц, совпадающие объединяются|

**Главное отличие:** `INNER JOIN` отбрасывает строки без совпадений, а `OUTER JOIN` сохраняет их со значениями `NULL` на стороне, где соответствия нет.

`LEFT JOIN` и `LEFT OUTER JOIN` — равнозначные записи. Аналогично, `RIGHT JOIN` и `RIGHT OUTER JOIN` обозначают одно и то же соединение.
