#### Плоский файл

**Плоский файл** — именованный набор данных на внешнем носителе.

**Недостатки**:
- для ОС это последовательность байт, поэтому структура записей определяется прикладной программой
- нельзя отдельно блокировать запись средствами ОС
- поиск записи по условию требует последовательного просмотра файла

---

#### База данных и основные понятия

**База данных (БД)** — именованная совокупность данных, отражающая состояние объектов и их отношений в рассматриваемой предметной области.

**Информационная система (ИС)** — система хранения и обработки информации.

**Автоматизированная информационная система (АИС)** — комплекс программных и технических средств и информационных массивов для сбора, хранения, поиска и выдачи информации.

**Банк данных (БнД)** — АИС централизованного хранения и коллективного использования данных.

**Система баз данных** = БД + СУБД + пользователи.

---

#### Предметная область

**Предметная область БД** — часть реального мира, информация о которой должна храниться, передаваться и обрабатываться в проектируемой системе.

**Анализ предметной области** — основа определения структуры БД. Определяют объекты, их свойства и связи между ними.

На основе анализа строится модель предметной области — её **формализованное описание**.

---

#### Работа с БД

*Пользователь → приложение → СУБД → БД*

Пользователем может быть человек, программа или устройство.

Конечному пользователю задаются необходимые права доступа, полный доступ ко всей БД ему не предоставляется.

**Трёхуровневая модель**:
- внешний уровень — представление для пользователя
- концептуальный уровень — логическое представление всей БД
- внутренний уровень — физическое хранение данных

#### Реляционная модель

В реляционной модели данные представлены **отношениями**.

**Схема отношения** — имя отношения и его атрибуты.

Пример: `Кинофильмы(Наименование, Год, Продолжительность, Жанр)`

Атрибуты схемы образуют множество, поэтому их порядок не имеет значения.

Значения атрибутов должны быть атомарными, то есть неделимыми в рамках данного отношения. Составные структуры, такие как массивы, списки и множества, в качестве одного значения не используются.

**Домен** — допустимое множество значений определённого типа, связанное с атрибутом.

**Кортеж** — строка таблицы.

**Отношение** — множество кортежей, соответствующих одной схеме отношения. Порядок кортежей не влияет на содержимое отношения.

**Экземпляр отношения** — конкретное множество кортежей, то есть текущее содержимое отношения.

Изменение данных изменяет экземпляр отношения. Изменение схемы называют эволюцией схемы БД.

#### Модели данных

- плоский файл
- ***иерархическая***
```
        A
       / \
      B   C
     / \
    D   E
```
- ***сетевая***
```
        A
       / \
      B ─ C
	 /
    D
```
- ***реляционная***
```
┌─────────────┐      ┌─────────────┐
│   Отделы    │      │ Сотрудники  │
├─────────────┤      ├─────────────┤
│ ID          │←─────│ Отдел_ID    │
│ Название    │      │ ID          │
└─────────────┘      │ ФИО         │
                     └─────────────┘
```
- объектно-ориентированная
- объектно-реляционная
- гибридная

Дополнительно преподаватель упоминал постреляционные модели и многомерные кубы.

#### Пользователи БД

- **Прикладные и системные программисты** — создают программы, использующие БД
- **Администраторы БД** — отвечают за техническое управление БД
- **Конечные пользователи** — работают с БД через приложения и имеют ограниченные права

---

#### Администратор БД

Отвечает за:
- концептуальную и физическую организацию БД
- безопасность и целостность данных
- резервное копирование и восстановление
- производительность.

---

#### СУБД

**СУБД (DBMS)** — программный комплекс для управления БД и работы приложений с данными.

**Основные функции**:
- управление данными во внешней памяти
- управление буферами оперативной памяти
- управление транзакциями
- журнализация и восстановление после сбоев
- поддержка языков БД

Центральной частью работы СУБД являются языки БД. В этом семестре изучается SQL.

**Классификация СУБД**:
- по модели данных:
	- иерархические
	- сетевые
	- реляционные
	- объектно-ориентированные
	- объектно-реляционные
- по степени распределённости: 
	- локальные
	- распределённые
- по способу доступа: 
	- файл-серверные
	- клиент-серверные
	- встраиваемые
